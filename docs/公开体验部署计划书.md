# 聆心平台 · 公开体验部署计划书

> 目标：让手机端、他人电脑端能通过一个链接打开使用「聆心」平台。
> 编写日期：2026-08-29 ｜ 版本：v1.0

---

## 一、结论先行

**可行性：可行，但要选对路径。** 本项目不能像普通网页一样"传上去就能用"，原因是它带有一批**本地重模型依赖**（torch、transformers、ultralytics、SenseVoice 语音情绪、ChromaDB）和**实时通信需求**（Socket.IO + WebRTC 视频）。但核心的对话/数字人/测评总结功能走的是**云端大模型 API（阿里云通义千问 DashScope）**，本地重模型只在"语音情绪 / 人脸情绪"时才用到，且**失败会自动降级**——这让"公开体验"的难度大幅下降。

**推荐分两步走：**

| 阶段 | 方案 | 成本 | 耗时 | 适用 |
|---|---|---|---|---|
| 短期（当天上线） | 本地启动 + 内网穿透 | ≈0 元 | 半天 | 临时演示、答辩、给熟人体验 |
| 正式（长期公开） | 国内云服务器 + 域名 + HTTPS | ≈ 350 元/年 | 部署 1~2 天 + 备案等待 1~2 周 | 24/7 稳定公开、比赛/答辩正式提交 |

## 二、项目部署画像（现状盘点）

### 2.1 技术栈

- **后端**：Flask + Flask-SocketIO（WebSocket 信令 + WebRTC 视频转发），`app.py` 作为入口
- **前端**：Vue 3 SPA（静态资源已本地化到 `static/`），Socket.IO 客户端，ECharts
- **数据库**：SQLite（`data/campus_mind.db`，约 1.4 MB，含 600 名种子学生）
- **向量库**：ChromaDB（`data/chroma_db`）
- **大模型**：阿里云 DashScope 通义千问 `qwen-plus`（**云端 API，已配置 Key**）
- **本地模型**（体积大、按需加载）：
  - YOLO v8 人脸检测（`yolov8n.pt`，6.5 MB，已在本仓库）
  - SenseVoice / emotion2vec 语音情绪（首次调用自动下载，数百 MB）
  - transformers FER 人脸情绪（首次调用从 HuggingFace 下载）

### 2.2 资源需求

| 形态 | 内存 | 磁盘 | 说明 |
|---|---|---|---|
| 完整版（含语音/人脸情绪） | ≥ 4 GB | ≥ 6 GB（torch 依赖 + 模型） | CPU 推理，视频/语音情绪较慢 |
| 精简演示版（仅文本 LLM + RAG） | ≥ 2 GB | ≥ 2 GB | 关闭/懒加载本地重模型，体验足够 |

### 2.3 部署的关键约束（必须提前知道）

1. **CORS / Socket.IO origin 硬编码为 localhost** —— `app.py:43-46` 只放行 `http://localhost:5000` 和 `http://127.0.0.1:5000`。**用公网域名访问时 WebSocket 会被拒绝，必须改。**
2. **摄像头/麦克风需要 HTTPS** —— 浏览器只在安全上下文（HTTPS 或 localhost）允许 `getUserMedia`。局域网 `http://192.168.x.x` 会被浏览器禁用摄像头。
3. **WebRTC 视频跨网需 TURN** —— 前端 `static/js/modules/video-call.js:181-184` 只配了公共 STUN，同一局域网可直连，**跨网/复杂 NAT 下会失败**。
4. **敏感数据** —— 处理的是学生心理健康数据（属敏感个人信息）。**公开演示务必只用种子假数据，切勿放入真实学生信息。**
5. **弱口令与弱密钥** —— 默认账号 `admin/admin123`、`SECRET_KEY=lingxin_secret_2026_change_in_production` 均为演示值，**公网必须更换**。

## 三、可行性分析

### 3.1 总体判断

| 维度 | 评估 | 说明 |
|---|---|---|
| 技术可行性 | ✅ 高 | 单机可跑，无外部基础设施强依赖 |
| 成本可行性 | ✅ 高 | 精简版可做到 0~350 元/年 |
| 网络可行性 | ⚠️ 取决于方案 | 国内访问优先选国内服务器；海外 PaaS 免费额度撑不住重依赖 |
| 安全合规 | ⚠️ 需整改 | 弱口令/弱密钥/API Key 需处理，敏感数据只放假数据 |
| 视频通话 | ⚠️ 有门槛 | 跨网需 TURN，成本与复杂度上升，可作为可选功能 |

### 3.2 三个方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 本地 + 内网穿透**（Cloudflare Tunnel / 花生壳 / frp） | 零迁移、模型已就绪、免费、当天上线 | 电脑需一直开机；CF Tunnel 国内访问慢/不稳（WebSocket/视频更差）；家宽上行带宽受限；免费 URL 不固定；视频跨网仍需 TURN | **适合短期演示** |
| **B. 国内云服务器**（阿里云/腾讯云轻量 + 域名 + HTTPS + Nginx） | 24/7 稳定、国内访问快、固定域名、HTTPS 正规、视频可用 | 要花钱（约 350 元/年）、国内域名需 ICP 备案（等 1~2 周）、部署工作量最大 | **★ 正式公开首选** |
| **C. 海外 PaaS**（Railway / Render / HuggingFace Spaces） | 免备案、HTTPS 自动、部署省事 | Render 免费档 512MB 内存 + 15 分钟休眠 + WebSocket 付费；Railway 无永久免费、AI 烧额度；**均撑不住 torch**；国内访问需翻墙/慢 | **不推荐**（除非目标用户都在海外） |

> 2026 年现状核验：Render 免费档 WebSocket 需付费、15 分钟闲置休眠、冷启动 30~60 秒；Railway 无永久免费档，AI/后台任务烧额度快；两者内存都 ≤512MB，跑不动 torch（约 2GB）。Cloudflare Tunnel 免费但无中国大陆节点，被戏称"减速云"，应用类/WebSocket 服务体验差。

### 3.3 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 重依赖安装失败/超时 | 无法启动 | 精简版裁剪依赖；用清华/阿里 pip 镜像；预下载 wheel |
| 本地模型首次下载失败 | 语音/人脸情绪不可用 | 该功能已有自动降级路径，演示可接受 |
| WebSocket 被 origin 拦截 | 实时功能全挂 | 部署前改 `app.py` CORS/Socket.IO origin 为域名 |
| 视频跨网打不通 | 视频通话不可用 | 加 TURN（coturn 自建），或演示阶段仅局域网/同网段用 |
| API Key 泄露 | 被盗刷 | 确认 `.env` 未提交 git；若曾分享则去阿里云控制台轮换 |
| 弱口令被爆破 | 数据被篡改 | 上线前改默认密码 + 强 SECRET_KEY |

## 四、推荐实施方案

### 方案 A（短期 · 当天上线 · 约 0 元）

1. **安全整改（必做，约 20 分钟）**
   - `.env` 里把 `SECRET_KEY` 换成强随机串：`python -c "import secrets; print(secrets.token_urlsafe(48))"`
   - 修改默认账号密码（`admin` / 辅导员 / 学工处 / 学生示例账号），或至少改 `admin`
2. **代码适配（约 30 分钟）**
   - `app.py`：把 CORS 与 Socket.IO 的 origin 改成允许你的穿透域名（或临时改为 `*`，演示用可接受）
3. **启动 + 穿透**
   - 双击 `演示一键启动.bat`（或 `python app.py`）
   - 用 **Cloudflare Tunnel**（`cloudflared tunnel --url http://localhost:5000`，生成临时 https 链接）或国内工具 **花生壳 / cpolar / frp**（国内访问更快更稳，部分需实名）
4. **手机/他人电脑验证**
   - 发链接给对方，用测试账号登录，验证：登录、聊天、情绪网络图、数字人回复、测评提交

> ⚠️ 方案 A 的局限：你的电脑要一直开机；免费隧道 URL 不固定且带宽有限；**视频通话跨网基本不可用**。适合"给评委/朋友现场或短时体验"，不适合长期挂公网。

### 方案 B（正式 · 长期公开 · 推荐）

#### 阶段 0：安全整改（同方案 A，务必先做）

#### 阶段 1：代码适配（约 1 小时）

1. `app.py` CORS/Socket.IO origin 改为你的正式域名（或环境变量读取，如 `ALLOWED_ORIGINS`）
2. 生产服务器：用 `gunicorn` + `eventlet/gevent` 跑（Flask 自带 dev server 不适合生产）
   ```bash
   pip install gunicorn eventlet
   gunicorn --worker-class eventlet -w 1 -b 127.0.0.1:5000 app:app
   ```
3. 可选：把本地重模型改为"懒加载 + 启动不下载"，加快启动、降低内存峰值

#### 阶段 2：服务器环境（约 1 天）

1. 购买**阿里云/腾讯云轻量应用服务器**：**2 核 4G**（完整版）约 **298 元/年**；**2 核 2G**（精简版，新用户秒杀）约 **38 元/年**。系统选 Ubuntu 22.04 / Debian。
2. 注册域名（`.com`/`.cn` 约 10~60 元/年），在云厂商完成 **ICP 备案**（需服务器包年包月 ≥3 个月，个人备案一般 1~2 周）。
3. 备案等待期间，可先用**服务器公网 IP** 直接访问（临时），或用已备案的临时域名。

#### 阶段 3：部署（约 1 天）

1. 上传代码（`git` 或 `scp`），创建 venv，`pip install -r requirements.txt`（用国内镜像）
2. 配置 `.env`（强 SECRET_KEY + DashScope Key + `DEBUG=false`）
3. `python seed_v31.py` 初始化种子数据（数据库/模型文件已 `.gitignore`，需在服务器上重新生成）
4. 可选：`tools/reindex_kb.py` 重建知识库索引
5. 用 `gunicorn` 启动，配 systemd 守护进程（开机自启 + 崩溃重启）
6. **Nginx 反向代理 + HTTPS（Certbot 免费证书）**，重点加 WebSocket 升级头（`proxy_set_header Upgrade $http_upgrade;` 等，见 `docs/安全部署指南.md`）

#### 阶段 4：验证（约 2 小时）

- 手机（4G/5G + Wi-Fi 各测一次）、他人电脑分别用测试账号走一遍：登录 → 聊天 → 数字人 → 网络图 → 测评 → 预约 → 预警工单
- 视频通话：若配置了 TURN 则测跨网；否则仅同网段验证

#### 阶段 5：运营

- 每日备份 `data/campus_mind.db`（crontab）
- 接入简单监控（`systemctl status` / uptime）
- 准备一份"体验账号清单"发给体验者

### 方案 C（PaaS，仅特殊场景）

若目标用户都在海外或可翻墙，可用 **HuggingFace Spaces**（免费 CPU 容器）跑精简版，或 Railway 短期试用。**不推荐作为国内公开体验主力。**

## 六、合规与安全要点（心理数据）

1. **只用种子假数据**：公开体验环境一律用 `seed_v31.py` 生成的确定性假数据，禁止导入真实学生信息。
2. **改默认口令 + 强 SECRET_KEY**：见方案 A 阶段 0，公网前必须完成。
3. **API Key 不外泄**：确认 `.env` 已 `.gitignore` 且未提交 git；若仓库曾公开/分享，去阿里云控制台**轮换 DashScope Key**。
4. **HTTPS**：正式公网必须启用，否则浏览器会禁摄像头/麦克风。
5. **危机数据提示**：若检测到自伤/自杀风险，平台有预警闭环；演示环境需在说明里标注"数据为演示用途"。

## 八、给你的建议

- **如果只是"答辩/比赛当天给评委扫个码体验"**：走**方案 A**，半天搞定，0 成本。
- **如果要"长期挂一个链接，谁都能随时打开"**：走**方案 B 精简版**（2 核 2G + 裁剪本地重模型），成本约百元级/年，国内访问快且稳定。
- **视频通话**是唯一"贵且麻烦"的功能（跨网要 TURN + HTTPS），建议先砍掉或仅局域网内演示，其余核心功能（聊天/数字人/情绪网络图/测评/预警闭环）都不受影响。
