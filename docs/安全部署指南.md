# 聆心平台 · 安全部署指南

> 聆心处理的是**学生心理健康数据**——情绪、测评结果、视频通话画面，均属于《中华人民共和国个人信息保护法》下的**敏感个人信息**。本指南覆盖从本地演示到真实部署必须补齐的安全措施。

---

## 一、密钥管理（最高优先级）

### 1. 强随机 SECRET_KEY

`.env` 中的 `SECRET_KEY` 用于签名登录令牌（JWT），一旦泄露攻击者可伪造任意身份。

```bash
# 生成强随机密钥（Linux/macOS / Git Bash）
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

将输出写入 `.env`：

```env
SECRET_KEY=粘贴上一步生成的48位以上随机串
```

> ⚠️ 生产环境若 `SECRET_KEY` 为空，`app.py` 会**拒绝启动**（开发模式除外）。切勿使用 `change-this-to-a-random-string` 这类占位值。

### 2. DashScope API Key 防泄露

- `.env` 已通过 `.gitignore` 排除，**永远不要提交到 git**。
- 若 Key 意外泄露：立即在阿里云控制台吊销并重新生成。
- 生产建议：API Key 走环境变量注入（如 systemd EnvironmentFile / 容器 secret），而非落盘明文。

### 3. 检查是否泄露

```bash
git check-ignore .env   # 应输出 .env，表示已忽略
```

## 二、强制 HTTPS

明文 HTTP 下，登录令牌、聊天内容、测评数据均可被中间人窃听。生产必须启用 TLS。

### Nginx 反向代理 + Certbot（推荐）

```nginx
server {
    listen 443 ssl;
    server_name lingxin.example.edu.cn;

    ssl_certificate     /etc/letsencrypt/live/lingxin/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/lingxin/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket / Socket.IO
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

server {
    listen 80;
    server_name lingxin.example.edu.cn;
    return 301 https://$host$request_uri;
}
```

> 注意：本项目前端视频通话依赖 `navigator.mediaDevices`（getUserMedia），浏览器**只允许在安全上下文**（HTTPS 或 localhost）使用摄像头/麦克风。局域网 HTTP 地址会被浏览器禁用。

## 三、WebRTC 视频通话跨网（TURN）

默认配置只用了公共 STUN，**同一局域网内可直连，跨网/复杂 NAT 下会失败**。生产需自建 TURN 服务器。

### 使用 coturn 部署 TURN

```bash
# 安装
apt install coturn

# /etc/turnserver.conf 关键配置
listening-port=3478
fingerprint
use-auth-secret
static-auth-secret=你的强随机串
realm=lingxin.example.edu.cn
```

前端在 `static/js/app.js` 的 `RTCPeerConnection` 配置里补充 TURN：

```js
iceServers: [
  { urls: 'stun:stun.l.google.com:19302' },
  {
    urls: 'turn:lingxin.example.edu.cn:3478',
    username: 'lingxin', credential: '你的TURN凭证'
  }
]
```

## 四、弱口令与账号安全

### 当前默认账号（演示用，生产必须改）

| 角色 | 默认口令 | 处理 |
|------|----------|------|
| 管理员 admin | `admin123` | 生产**必须修改** |
| 辅导员 | `counsel123` | 生产**必须修改** |
| 学工处 | `staff123` | 生产**必须修改** |
| 学生 | `123456` | 生产改为随机初始密码并强制首登改密 |

### 已内置的防护

- ✅ 登录频率限制（同 IP 5 分钟 30 次）
- ✅ 登录失败审计（记录用户名 + IP 到 `system_logs`）
- ✅ 学生注册密码复杂度校验（≥6 位、非纯数字、非学号）
- ✅ 令牌注销黑名单

### 建议增强（按需）

- 密码复杂度策略扩展到教师端（含大写/数字/符号）。
- 关键操作（导出数据、重置密码、危机上报）二次鉴权。
- 管理员账号启用强口令 + 定期轮换。

## 五、敏感数据保护

### 1. 最小化授权

- 辅导员只能访问**本人学生**（已通过 `counselor_id` 隔离实现）。
- 管理员/学工处可全量查看——生产应细分为「按学院」「按分管范围」授权。

### 2. 数据加密与脱敏

- 数据库文件 `data/campus_mind.db` 建议置于加密磁盘/卷。
- 测评结果（PHQ-9/GAD-7/ISI）与视频通话情绪数据属高度敏感项，导出时建议脱敏（隐藏学号/姓名，仅保留统计）。
- 视频画面与音频**不落盘**（当前仅实时分析，无存储），若需留存须单独加密并征得同意。

### 3. 访问审计

- 已有 `system_logs` 操作日志（`@log_action` 装饰器自动记录）。
- 生产建议接入集中日志系统，并设置 90 天以上保留（`SecurityConfig.LOG_RETENTION_DAYS`）。

## 六、合规要点（心理数据）

1. **知情同意**：学生首次使用时应明确告知数据收集范围、用途、保存期限。
2. **目的限制**：情绪/测评数据仅用于心理健康支持，不得用于学业评价、奖惩等无关用途。
3. **危机干预义务**：检测到自伤/自杀风险（PHQ-9 第 9 项、视频通话高危情绪）时，系统应触发人工介入流程（见危机干预闭环），并遵循「生命优先」原则。
4. **数据删除权**：学生有权要求删除其个人数据，需提供删除入口。

## 七、备份与恢复

```bash
# 备份数据库（建议每日定时）
cp data/campus_mind.db data/backup_$(date +%Y%m%d).db

# 恢复
cp data/backup_20260819.db data/campus_mind.db
```

> SQLite 备份务必在应用停止或低峰时进行（或使用 `sqlite3 .backup` 在线备份）。
