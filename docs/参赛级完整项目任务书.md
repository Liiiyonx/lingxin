## 二、总体目标与验收标准

「参赛级完整项目」的验收标准：

1. **可交付**：`git clone` 后一条命令启动，评委可当场运行；
2. **可读**：代码按业务分模块，不是巨型单文件；
3. **可信**：核心闭环有自动化测试守住，改代码不会悄悄破坏；
4. **可讲**：README/答辩材料能在 3 分钟讲清「做了什么、亮点在哪、怎么验证」。

## 三、任务清单

### P0 — 工程固化（半天，最优先）

#### P0-1 git 提交全部工作
- **目标**：把 14 个未提交文件纳入版本控制，杜绝成果丢失。
- **现状**：`core/digital_human.py`、`tests/test_closed_loop.py`、`purify.min.js`、状态聚合修复、网络图增强等均未提交。
- **实现方法**：
  1. `git add -A`
  2. 按逻辑拆成多个 commit（建议：`feat: AI数字人` / `feat: 状态聚合与风险证据时间线` / `feat: 危机工单与预约联动` / `fix: XSS防护(DOMPurify)` / `test: 闭环回归测试`）；
  3. 提交前 `git status` 确认 `.env`、`data/*.db`、模型文件未被误跟踪。
- **验收**：`git status` 干净，`git log` 覆盖全部功能。

#### P0-2 修复测试运行环境
- **现状**：`tests/` 无 `__init__.py`，`python -m unittest tests.test_closed_loop` 会报 ModuleNotFound；requirements 未声明测试依赖。
- **实现方法**：
  1. 新建 `tests/__init__.py`（空文件）；
  2. requirements.txt 增加 `pytest`；
  3. 验证 `python -m pytest tests/ -q` 能跑通。
- **涉及文件**：`tests/__init__.py`、`requirements.txt`。
- **验收**：`pytest tests/` 全绿。

### P1 — 测试补齐（第 1 周）

#### P1-1 后端补充测试用例
- **目标**：把「有测试」升级为「测试有覆盖」。
- **现状**：仅 `test_closed_loop.py`（1 个闭环用例）+ `test_routes.py`（较薄）。
- **实现方法**：新增 `tests/test_features.py`，覆盖以下场景：
  1. **数字人危机**：`generate_reply("我想死")` 返回 `crisis=True`；模拟离线消息触发后，断言生成了 `AlertLog`；
  2. **预警状态机**：pending → acknowledge（重复确认返回 400）→ resolve → 学生风险被重算；
  3. **测评边界**：item9≥2 生成高危预警并回写；item9=0 但 PHQ≥10 生成 medium 回写；
  4. **预约联动**：confirmed 生成 Todo；completed 生成 StudentProfile；
  5. **权限隔离**：辅导员访问他人学生返回 403 或空。
- **涉及文件**：`tests/test_features.py`。
- **验收**：`pytest` 用例数 ≥ 10，全部通过。

#### P1-2 前端冒烟测试
- **目标**：防止再次出现「白屏」这类前端编译错误。
- **现状**：前端零自动化测试（上次白屏正是缺这种兜底）。
- **实现方法**（选一）：
  1. **轻量（推荐）**：写一个 `scripts/smoke_frontend.py`，用 `subprocess` 调 Edge headless `--dump-dom`，断言页面含「欢迎使用聆心」等关键文本；或
  2. **正式**：引入 Playwright，写 `tests/e2e_login.py`，覆盖登录 → 进入工作台 → 打开网络图。
- **涉及文件**：`scripts/smoke_frontend.py` 或 `tests/e2e_login.py`。
- **验收**：前端改动后能自动发现「页面渲染失败」。

### P2 — 架构重构（第 1-2 周，最大项）

#### P2-1 拆分 routes.py（4099 行 → 多 blueprint）
- **目标**：按业务域拆分，消除巨型文件。
- **实现方法**：在 `api/` 下新建子模块，每个是独立 `Blueprint`，`app.py` 统一注册：
  ```
  api/
    routes.py          → 保留为「聚合注册」入口
    auth.py            → 登录/注册/学生认证（337-447 行）
    messages.py        → 通讯 + 数字人 + 话术 + 谈心报告（520-1240 行）
    conversation.py    → 班会/公文/组织整理/识别（1373-1930 行）
    emotion.py         → 语音/实时情绪/看板（1932-2655 行）
    network.py         → 情绪网络图（2655-2684 行）
    alert.py           → 预警/危机工单（2684-2890 行）
    student.py         → 学生管理/提醒/待办/日历（3047-3333 行）
    assessment.py      → 测评/危机上报（3418-3570 行）
    knowledge.py       → 知识库
    system.py          → 系统/导出/reseed
  ```
- **关键点**：共享的 `db/auth/emit_*` 等单例，抽到 `api/common.py` 或 `api/extensions.py` 统一 import，避免循环依赖。
- **涉及文件**：`api/*.py`、`app.py`。
- **验收**：单文件 ≤ 1000 行；`pytest` 全绿（拆分后行为不变）。

#### P2-2 拆分 app.js（2767 行）与 index.html（1017 行）
- **目标**：前端按功能拆模块，消除两个巨型文件。
- **实现方法**：
  1. **先拆 app.js**：把「数字人」「网络图」「测评」「预约」等相对独立的状态与函数抽成 `static/js/modules/digitalHuman.js`、`networkView.js`、`assessment.js` 等，用 `window.ModuleName = { setup, methods }` 暴露，`app.js` 里调用组装（保持无构建、不引入打包器，降低迁移风险）；
  2. **再拆 index.html**：17 个页面的 `v-if` 块抽成 `templates/partials/*.html`，用 `<template>` + 服务端 `include`（Flask `render_template` 或简单拼接）或前端动态加载；
  3. 拆分顺序「由近及远」：先数字人、网络图（刚写的、耦合低），再老模块。
- **涉及文件**：`static/js/app.js`、`static/js/modules/*`、`templates/index.html`、`templates/partials/*`、`app.py`。
- **验收**：`app.js` ≤ 1500 行；前端冒烟测试通过。

#### P2-3 database.py 拆分（可选，2684 行）
- **实现方法**：按实体拆 DAO 到 `core/models/*.py`（模型）+ `core/dao/*.py`（操作），或至少把 `DatabaseManager` 按域拆成多个 Mixin。
- **优先级**：低（不影响演示，评委深入看才涉及）。

### P3 — 健壮性与体验（第 2-3 周）

#### P3-1 清理静默错误处理
- **现状**：`api.js` 仍有多处 `catch { /* silent */ }`（轮询静默可保留，关键操作需提示）。
- **实现方法**：在 `api.js` 维护一个「关键路径白名单」`['/messages/send','/conversation/generate-report','/crisis/report','/assessment/submit']`，白名单内失败时 `emitter.emit('error', ...)` 触发 Toast；轮询/上传仍静默。
- **涉及文件**：`static/js/utils/api.js`。
- **验收**：断网时发送消息会弹出错误提示，而非静默失败。

#### P3-2 首屏懒加载
- **现状**：登录页会拉取 echarts、face-api、marked、socket.io 等全部依赖。
- **实现方法**：echarts/face-api 已按需加载（保留）；`marked`/`socket.io` 改为「进入对应页面时才注入」；数字人 TTS、网络图模块同理。
- **验收**：登录页 Network 面板依赖数明显减少。

#### P3-3 移动端适配（重点页）
- **现状**：网络图（canvas 固定尺寸）、视频、聊天在手机不可用。
- **实现方法**：优先做「学生端聊天 + 测评」两个高频移动场景的响应式（flex 断点 + 触控）；网络图加「移动端禁用缩放、改用双指手势」或提供列表降级视图。
- **优先级**：中（若答辩用手机演示则提前）。

#### P3-4 ECharts 实例复用
- **实现方法**：`renderEmoCharts` 中不再每次 `dispose` + `init`，改为「首次 init、后续 setOption」；页面离开时再 dispose。
- **涉及文件**：`static/js/app.js`。
